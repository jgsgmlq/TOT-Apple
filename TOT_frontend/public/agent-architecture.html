2. 节点详解

代码 01 · LoadContext
加载用户长期记忆和注入用户消息到对话历史。
输入
state.userId, state.userMessage
输出
memory_snippets (用户偏好/上下文), messages (追加 HumanMessage)
核心逻辑
调用 chatMemoryService.getMemories() 读取 Store API，失败降级为空
Trace
node_enter → node_exit (snippets 数量)
LLM 02 · SafetyGateway
安全路由网关。分析用户意图，判断是否为禁止请求、纯闲聊、含歧义、或需要工具查询。
LLM
routerModel — DeepSeek Chat · temperature=0.1 · maxTokens=512
Prompt
safety_gateway — 含近期对话历史(最近4轮)
输入
state.userMessage, state.messages, state.memory_snippets
输出
mode (chat/deny/tool), extracted_task_ref, extracted_org_ref, extracted_org_type, extracted_time_ref, ambiguity_payload
路由
deny → FinalResponseStep (拒绝回答)
chat → FinalResponseStep (纯闲聊)
hitl → HumanInTheLoopGate (有歧义需确认)
fc → fc_CheckSteps (工具查询)
纠错
correctMode() — chat + 检测到实体引用 → 升级为 tool
Trace
node_enter → decision(mode) → node_exit
代码 03 · fc_CheckSteps
FC 循环步数控制器。检查是否超出最大轮次限制。
输入
state.fc_super_step_count, state.hitl_resume_payload
输出
fc_super_step_count (递增), fc_next_action
规则
从 HITL 恢复不递增步数 (ask_user 不消耗 FC 轮次)
超出 MAX_FC_ROUNDS(默认3) → 强制 FinalResponseStep
Trace
node_enter → node_exit (step, fromHitl)
LLM 04 · fc_LlmToolCallStep
FC 循环核心：LLM 决定调用哪些工具(或直接回答)。
LLM
fcModel — DeepSeek Chat · temperature=0.1 · maxTokens=2048 · streaming=true
支持 DEEPSEEK_REASONER 切换 deepseek-reasoner
Prompt
fc_agent — 含实体提取、图表数据、工具列表 (bindTools)、步数上下文
输入
完整消息历史 (截断30条), state.toolResults, state.extracted_*
输出
messages (追加 AIMessage + tool_calls), 无工具调用时直接输出 reply_markdown
流式
逐 token 通过 SSE emitter 发送 (isReasoning: true)
DSML 过滤: 过滤 <｜tool_calls> 乱码段
超限
达到 maxSteps 时: 不绑定工具, 追加 SYSTEM 指令强制总结
Trace
node_enter → llm_generation (step, chunks, latencyMs, toolCallCount, toolCallNames) → node_exit
代码 05 · fc_CheckDuplicate
工具调用去重。三级缓存：同批去重 → 同图缓存 → 跨会话 Session 缓存。
输入
最后一条 AI 消息的 tool_calls
输出
pending_tool_calls (需执行的新调用)
toolResults (缓存命中直接注入结果)
fc_next_action: validate/merge/finalize
签名
buildToolSignature(toolName, args, scopeFp, freshnessBucket) — 相同签名 = 相同查询
Freshness 桶
realtime=60s, daily=3600s, static=86400s
Trace
node_enter → decision(total/deduped/pending) → node_exit
代码 06 · fc_ExecuteTool
工具执行器。串行调用每个待执行的工具，支持超时保护、权限短路、SSE 事件。
输入
state.pending_tool_calls
输出
toolResults (key=call_id, value={data, signature, error})
calledTools (已执行工具名列表)
fc_next_action: merge/hitl
特殊处理
ask_user 工具 → 走 HITL 中断路径
PERMISSION_DENIED → 后续工具短路跳过
超时保护: 每个工具独立 timeoutMs
SSE
emitter.handleToolStart / handleToolEnd
Trace
node_enter → tool_call → tool_result → node_exit (executed: N, tools: [...])
代码 07 · fc_MergeToolResults
将工具执行结果转换为 ToolMessage 注入对话历史，供下一轮 LLM 使用。
输入
state.toolResults, state.messages
输出
messages (追加 ToolMessage), pending_tool_calls (清空), fc_next_action
逻辑
找到最后一条含 tool_calls 的 AI 消息
跳过已 emit 的 tool_call_id
alias_of 解引用 (同批去重)
空结果 → 注入错误 payload + fallback 计数
缓存
成功结果写入 Session 缓存 (chatSessionStateService.addRecord)
Trace
node_enter → node_exit (merged: N, fallbacks: N)
混合 08 · HumanInTheLoopGate
人机交互中断 & 恢复节点。LangGraph interrupt() 挂起图执行，等待用户响应后恢复。
触发
SafetyGateway ambiguity_payload 或 fc_ExecuteTool 的 ask_user
中断
interrupt(payload) — 图挂起, SSE 发 clarify + done 事件, 前端渲染选择界面
恢复
前端发 resume 请求 → Command({resume}) → 此节点继续执行
5 条路径
fc_hitl_continue — FC 澄清继续 (用户回复注入 HumanMessage)
fc_hitl_cancel — FC 澄清取消 → finalize
cancel — 顶层取消 → finalize
intent_shift — 意图转移 → re_route (重置实体+消息)
slot_fill — 补全参数 → validate (重新执行工具)
任务候选
missing_task_ref 时自动查询最多8个任务供选择
Trace
node_enter → decision(5条路径) → node_exit
LLM 09 · FinalResponseStep
最终回复生成。将工具结果和图表数据交给 LLM，输出结构化 JSON。
LLM
structuredModel — DeepSeek Chat · temperature=0.1 · maxTokens=2048 · response_format=json_object
Prompt
final_response + 用户问题 + 工具结果 JSON + 可用数据集摘要
输入
state.toolResults (所有工具结果), state.userMessage
输出
结构化 JSON (Zod 校验 TemplateOutput):
6 模板
simple_metric — 单指标 (keyNumbers 突出)
ranking — 排名 (图表+表格)
overview — 全景 (keyNumbers+图表)
warning — 预警 (attentionPoints 突出)
diagnosis — 诊断 (attentionPoints+建议)
general — 通用 (纯 markdown)
数据解析
extractPlottableData() — 从工具结果提取可画图数据集
LLM 通过 selectedCharts/selectedTables 引用
↔ 代码按 datasetId 匹配 → 生成 charts + tables 数组
降级
无工具结果 → 纯闲聊路径 (stream 文本)
JSON 解析失败 → 降级 renderToolResultsMarkdown
Trace
node_enter → node_exit (template, tables, charts, bytes)
代码 10 · PersistAndEmit
持久化消息到 MySQL + 发送 SSE done 事件 + 生成会话标题 + 发布记忆事件。
输入
state.finalResponse, state.reply_markdown, state.sessionId
输出
finalMessageId, sessionTitle
核心逻辑
1. 解析 reply_markdown JSON → 提取 overview 为 contentText
2. 注入 _trace (state.trace_log) 到 contentJson
3. 写入 chat_message 表
4. 首次回复自动生成会话标题 (LLM titleModel)
5. 发布 memory 事件到 BullMQ
6. 更新 Langfuse trace 元数据
Trace
node_enter → node_exit (messageId) → clearT0

3. 条件路由决策

路由点条件目标说明
routeAfterSafetyGateway mode === "deny"FinalResponseStep拒绝请求(非只读/敏感内容)
mode === "chat"FinalResponseStep纯闲聊(无数据查询)
ambiguity_payloadHumanInTheLoopGate有歧义(缺任务名/范围不明)
其他fc_CheckSteps工具查询 → 进入 FC Loop
routeAfterFcCheckSteps step >= MAX_FC_ROUNDS(3)FinalResponseStep超出最大轮次,强制回答
正常fc_LlmToolCallStep继续 FC 循环
routeAfterFcLlm LLM 返回 tool_callsfc_CheckDuplicate有工具调用 → 去重后执行
无 tool_callsFinalResponseStepLLM 认为信息够 → 直接回答
routeAfterCheckDuplicate pending_tool_calls > 0fc_ExecuteTool有新调用需执行
全部去重fc_MergeToolResults直接用缓存结果
routeAfterExecute hitl_status === 'pending_interrupt'HumanInTheLoopGateask_user 触发中断
escalate_count >= 1FinalResponseStep执行异常,跳过后续
正常fc_MergeToolResults合并结果继续
routeAfterMergestep >= MAX_FC_ROUNDS(3)FinalResponseStep超轮次 → 最终回答
正常fc_CheckSteps回到 FC 循环开始
routeAfterHumanInTheLoop fc_next_action === "finalize"FinalResponseStep取消/退出
正常fc_CheckSteps回到 FC 循环

6. State 数据流

State 使用 LangGraph Annotation 模式，不同字段有不同的 reducer 策略。节点只写自己拥有的字段。

sessionId / userId / userMessage 入口设定
会话标识和用户输入。入口(chatService)一次性写入。
messages 追加模式(concat)
对话历史。LoadContext 注入首条 HumanMessage，FC 节点注入 AIMessage + ToolMessage。
memory_snippets LoadContext
用户长期记忆(偏好/上下文)。被 SafetyGateway 和 fc_LlmToolCallStep 渲染进 prompt。
mode / intent SafetyGateway
路由决策: chat_only | tool_action | deny。intent 用于 FinalResponseStep 的模板选择。
extracted_task_ref / extracted_org_ref / extracted_org_type / extracted_time_ref SafetyGateway
从用户消息中提取的实体。注入 fc_agent prompt 帮助 LLM 选工具。
ambiguity_payload SafetyGateway
歧义检测结果。触发 HumanInTheLoopGate 中断。
fc_super_step_count fc_CheckSteps
FC 循环轮次计数器。多个路由点检查此值决定是否强制终止循环。
pending_tool_calls fc_LlmToolCallStep, fc_CheckDuplicate
待执行的工具调用列表。fc_ExecuteTool 消费，fc_MergeToolResults 清空。
toolResults fc_ExecuteTool (merge spread)
{tool_call_id: {data, signature, error}} 累计。多轮 FC 结果累积。
calledTools fc_ExecuteTool (concat)
所有已执行工具名列表。用于 trace 和 done 事件的 _toolMeta。
hitl_status / interrupt_payload / hitl_resume_payload HITL 节点
人机交互状态: idle → pending_interrupt → resumed。恢复时携带用户选择。
finalResponse / reply_markdown FinalResponseStep, fc_LlmToolCallStep
最终回复(JSON 字符串或 Markdown)。PersistAndEmit 消费。
trace_log 各节点 (concat 追加)
运行追踪事件数组。PersistAndEmit 写入 content_json._trace。
regionScope 入口设定
用户权限范围: {type: "national" | "regional" | "rtm", regions, rtm}。工具执行时传递。

7. SSE 事件流

事件phase/内容来源节点前端处理
delta phase=reasoning · LLM 推理文本 fc_LlmToolCallStep 累积到 thinking (思考过程面板)
delta phase=tool_start · {toolName} fc_ExecuteTool 显示"正在查询 XXX" 旋转指示器
delta phase=tool_end · {status} fc_ExecuteTool 移除旋转指示器
delta phase=content · 最终回复文本 FinalResponseStep (chat_only 路径) 渲染到 hero card 或 markdown
trace {ts, type, node, data} 所有节点 (runTrace) 累积到 traceSteps → AgentTracePanel
clarify {prompt, options, threadId} PersistAndEmit (HITL 路径) 渲染选择器界面
done {messageId, replyContent, markdownContent, _toolMeta} PersistAndEmit 最终确定消息状态
error {message, code} chatService (异常捕获) 显示错误提示
